# 데이터 보관 구조

이 폴더는 현재 정적 앱에 들어 있는 데이터를 **원본(Raw) → 1차 가공(Processed) → 앱 표시용(App)** 으로 나눠 보관하기 위한 기준점입니다. 기존 화면과 선택 방식은 그대로 두고, 데이터가 서로 덮어써지지 않도록 보관·검증 경로를 먼저 분리했습니다.

## 폴더 규칙

```text
data/
├── raw/         원본 파일·원본 응답의 보관 위치와 출처 기록
├── processed/   정규화·필터·월말 집계가 끝난 1차 가공 스냅샷
├── app/         file://에서도 읽을 수 있는 앱용 JS 어댑터
├── checks/      데이터 개수·중복·길이 검증 스크립트
└── manifest.json 데이터셋별 기준 경로·상태·개수
```

### 1. Raw Data

원본 엑셀, SEC 원문 XML, 원본 웹 응답처럼 **다시 가공할 수 있는 최초 입력**입니다. Raw는 덮어쓰거나 수동 수정하지 않습니다. 현재 이 프로젝트 미러에는 원본 파일 자체가 동기화되어 있지 않아 `raw/source-register.json`에 출처와 미보유 상태를 기록했습니다. 원본을 확보하면 먼저 `raw/`에 날짜·출처를 포함한 새 파일로 넣고, 기존 파일은 교체하지 않습니다.

### 2. Processed Data (1차 가공)

현재 앱에 사용되는 스냅샷입니다. ETF는 `STOCKHISTORY`의 일별 Close를 월별 마지막 관측값으로 집계했고, 밸류에이션은 QQQ N-PORT 유니버스와 분기별 비율 조회 결과를 결합했으며, 저PER 데이터는 62개 후보 풀에 Fiscal Q1 2025 조건을 적용한 결과입니다. 이 단계에는 변환·필터가 들어갔으므로 Raw와 동일하다고 부르지 않습니다.

감사 대상 행(COPX, XLY 등)과 `status`가 `partial`·`missing`인 값도 삭제하지 않고 그대로 남깁니다. 분석에서 제외하는 것과 보관하지 않는 것은 다릅니다.

### 3. App Data

정적 `file://` 페이지에서 사용할 수 있도록 Processed 스냅샷을 `window.*` 전역으로 노출하는 JS 어댑터입니다. 다만 현재 앱에서는 기존 사용자 편집을 보호하기 위해 자동으로 로드하지 않습니다. `index.html`의 임베드 데이터와 `screen_low_pe_q1_2025.js`가 현재 화면의 실제 원본이며, `app/` 파일은 검증된 분리본입니다. 두 계층을 자동으로 합치거나 우선순위를 바꾸지 않습니다.

## 데이터셋 안내

- `etf-monthly`: 26개 ETF, 333개월, 원시 행 6,948개. 사용 가능 시계열 24개, 감사 시계열 2개. `bridge`는 수익률이 아니라 기준 경로에서의 기하학적 이탈 진단값입니다.
- `valuation-q1-2025`: Fiscal Q1 2025, 최종 기업 데이터 100행. Q1·최근 시가총액 지도와 원천 메타데이터를 함께 보관합니다.
- `low-pe-q1-2025`: 후보 풀 62개를 보관하고, 그중 조건을 통과한 19개를 `screen.selectedCount`로 기록합니다. 후보 행 자체도 삭제하지 않습니다.

## 작성기(Writer) 데이터 주의

사용자가 작성한 개인 분석은 `writer.js`의 브라우저 `localStorage`에 저장되며 프로젝트 파일과 별도입니다. 기본 저장 키와 함께 마지막 정상 상태를 보관하는 안전 백업 키도 갱신하도록 바꿨습니다. 그래도 브라우저 프로필·파일 출처가 바뀌면 저장소가 달라질 수 있으므로, 큰 변경 전에는 화면의 **기록 백업하기** 기능으로 JSON 백업을 먼저 내려받아 두세요. 이 폴더에는 로그인 정보나 개인 작성 내용을 복사하지 않습니다.

## 갱신 순서

1. 원본을 `raw/`에 새 버전으로 보관하고 `source-register.json`에 출처·수집일을 적습니다.
2. 변환·필터·집계 결과를 `processed/`에 새 스냅샷으로 생성합니다. 기존 스냅샷을 먼저 덮어쓰지 않습니다.
3. 기존 화면 소스를 먼저 백업하고, 분리본이 필요할 때만 `node data/checks/build-app-adapters.js`를 실행합니다. 이 명령은 `data/app/`만 갱신하며 `index.html`·`screen_low_pe_q1_2025.js`를 수정하지 않습니다. active source와 Processed가 다르면 안전을 위해 중단합니다.
4. `node data/checks/validate-data.js`와 `node data/checks/check-source-drift.js`를 실행합니다. 값이 다르면 덮어쓰지 말고 어느 쪽을 기준으로 삼을지 결정합니다.
5. 개수·기간·중복·감사 행을 확인한 뒤에만 화면 연결을 바꿉니다.

## Quant × Trend 연결 데이터

일별 시장 데이터는 기존 Q1·ETF·작성기 데이터와 섞지 않고 별도 경로를 사용합니다.

```text
data/raw/market/                 공급처 원문 응답
data/processed/quant-trend/      정규화·Trend 8조건 계산 스냅샷
data/app/quant-trend-snapshot.js 화면이 선택적으로 읽는 어댑터
scripts/quant-trend-pipeline.js  수집·정규화·계산·출력 파이프라인
```

기본 흐름은 `Raw → 정규화 → Processed → App`입니다. API 키가 없을 때는 임의 가격을 채우지 않고 화면을 연결 대기로 유지합니다. 수집이 부분적으로 실패하면 성공 행을 숨기지 않되 `quality.status: partial`과 ticker별 오류를 함께 남깁니다. 같은 경로의 스냅샷은 `--force`를 명시해야 교체됩니다.

## 손실 방지 원칙

- Raw와 Processed를 같은 파일에 섞지 않습니다.
- 원본 행·실패 행·감사 행을 임의로 삭제하지 않습니다.
- 화면용 반올림·라벨 변경은 App 계층에서만 합니다.
- `manifest.json`의 `canonicalPath`는 Processed 계층의 기준 파일이며, 화면에 실제로 쓰는 active source와 자동으로 우선순위를 바꾸지 않습니다.
- 파일을 바꾸기 전 Writer 백업과 Processed 스냅샷을 함께 남깁니다.
